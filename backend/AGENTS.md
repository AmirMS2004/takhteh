# بک‌اند

FastAPI روی Python 3.13، مدیریت پکیج با `uv`.

- `app/main.py` — اپلیکیشن FastAPI؛ مسیرهای `/api/*` و در انتها mount فایل‌های استاتیک از `static/` روی `/`. صفحه‌ها با `Cache-Control: no-cache` ارسال می‌شوند تا مرورگر پس از بازسازی، نسخه قدیمی را نشان ندهد. کلید سشن از `SESSION_SECRET` یا فایل `data/session_secret` (در نبودش ساخته می‌شود) خوانده می‌شود.
- `app/db.py` — اتصال `sqlite3` (`connect()` با commit/rollback خودکار)، ساخت جدول‌ها، مهاجرت پایگاه داده‌های قدیمی (`_migrate`، از جمله بازسازی `boards`) و seed کاربر `user` و برد دمو در `init_db()` هنگام شروع، هش رمز با scrypt، `create_user` و `create_board` (پنج ستون، برچسب‌های پیش‌فرض و ردیف مالک). مسیر فایل: `data/app.db` یا متغیر `DB_PATH`. طرح در `docs/DATABASE.md`.
- `app/board_service.py` — همه خواندن و نوشتن‌های برد. دسترسی با عضویت در برد (`board_members`) کنترل می‌شود؛ برد، ستون، کارت یا برچسبی که کاربر عضو بردش نیست `NotFound` (404) می‌دهد؛ کار مخصوص مالک برای عضو `Forbidden` (403) و عضو تکراری `Conflict` (409). شناسه‌های API به شکل `board-N`، `col-N`، `card-N` و `label-N`. برچسب‌های کارت و ستون مقصد جابه‌جایی باید از همان برد کارت باشند. پارامتر `board_id` هر عملیات را به یک برد محدود می‌کند (AI از آن استفاده می‌کند). `assignee` نام کاربری یکی از اعضای برد است (`assignee_id` در پایگاه داده). AI در بخش نهم هم از همین ماژول استفاده می‌کند.
- `app/board.py` — مسیرهای `GET/POST /api/boards`، `GET/PATCH/DELETE /api/boards/{id}`، `POST /api/boards/{id}/members` (بدنه `{username}`)، `DELETE /api/boards/{id}/members/{username}` (مالک عضو را حذف می‌کند یا عضو خودش خارج می‌شود؛ مالک نمی‌تواند خارج شود)، `POST /api/boards/{id}/labels`، `POST /api/boards/{id}/columns` (ستون تازه در انتها)، `DELETE /api/columns/{id}` (با کارت‌هایش؛ آخرین ستون برد 409)، `POST /api/columns/{id}/move` (بدنه `{index}`)، `PATCH /api/columns/{id}`، `POST /api/cards`، `PATCH /api/cards/{id}`، `POST /api/cards/{id}/move`، `DELETE /api/cards/{id}`. کارت‌ها جزئیات اختیاری `due_date`، `priority` و `assignee` و فهرست `labels` (شناسه برچسب‌های همان برد) دارند (نوع‌های مشترک `DueDate`، `Priority`، `Assignee` که AI هم استفاده می‌کند). برچسب‌ها: `POST /api/boards/{id}/labels`، `PATCH /api/labels/{id}`، `DELETE /api/labels/{id}` (`name` اختیاری تا ۳۰ کاراکتر، `color` یکی از شش رنگ `LabelColor`)؛ شناسه‌ها `label-N`. برد برگشتی `labels` برد را هم دارد. در `PATCH` فقط فیلدهای فرستاده‌شده تغییر می‌کنند و `null` یک فیلد اختیاری را پاک می‌کند.
- `app/auth.py` — `POST /api/auth/login`، `POST /api/auth/signup` (حساب تازه با برد خالی پنج‌ستونی و ورود خودکار؛ نام تکراری 409)، `POST /api/auth/password` (تغییر رمز با رمز فعلی؛ رمز نادرست 403)، `POST /api/auth/logout`، `GET /api/auth/me` (`{username, name, email, avatar}`)، `PATCH /api/auth/profile` (فقط فیلدهای فرستاده‌شده تغییر می‌کنند؛ نام کاربری تکراری 409؛ ایمیل خالی یا یک نشانی ساده؛ `avatar` از ۰ (حرف اول نام کاربری) تا ۸ (عکس‌های آماده‌ای که فرانت‌اند می‌کشد)). تغییر نام کاربری حساب و سشن را عوض نمی‌کند، چون همه‌جا شناسه کاربر ذخیره می‌شود. `GET /api/boards` برای هر برد شمار اعضا، کارت‌ها و کارت‌های با مسئولیت کاربر (`members`، `cards`، `my_cards`) را هم می‌دهد و اعضای برد `avatar` دارند. نام کاربری ۳ تا ۳۲ حرف انگلیسی، عدد یا `_` است و به حروف کوچک تبدیل می‌شود (ورود به بزرگی و کوچکی حروف حساس نیست)؛ رمز دست‌کم ۸ کاراکتر و dependency به نام `current_user` برای محافظت از مسیرها. سشن در کوکی امضاشده `SessionMiddleware`؛ کلید در `app/main.py` تعیین می‌شود.
- `app/ai.py` — کلاینت OpenAI روی Groq (`openai/gpt-oss-120b`، وقتی `GROQ_API_KEY` تعریف شده باشد) یا OpenRouter (`particle-ai/particle-1:free`)؛ `AI_PROVIDER` و `AI_MODEL` انتخاب را تغییر می‌دهند (جدول `PROVIDERS`) و توابع `chat(messages, response_format=None)` و `stream_chat` (همان، ولی متن را تکه‌تکه برمی‌گرداند)؛ روی OpenRouter، با `response_format` فقط providerهایی انتخاب می‌شوند که آن را پشتیبانی کنند (`provider.require_parameters`، که به Groq فرستاده نمی‌شود). نبود کلید ارائه‌دهنده یا خطای آن `AIUnavailable` (پاسخ 503) می‌دهد؛ محدودیت نرخ (مثلاً سهمیه روزانه مدل‌های رایگان) `AIRateLimited` (پاسخ 429). مهلت هر درخواست ۶۰ ثانیه با یک تلاش مجدد.
- `app/ai_routes.py` — `POST /api/ai/chat` با بدنه `{board_id, message}`: برد انتخاب‌شده (با اعضایش) به‌صورت JSON در پیام سیستمی، به‌همراه ۲۰ پیام آخر گفت‌وگوی ذخیره‌شده (`MAX_HISTORY`) و پیام جدید، به مدل فرستاده می‌شود. گفت‌وگو برای هر کاربر و هر برد در جدول `chat_messages` ذخیره می‌شود؛ فقط نوبت‌های کامل (پیام کاربر و پاسخ) ذخیره می‌شوند و نوبت ناموفق (502، 503، 429) نه. `GET /api/ai/history/{board_id}` گفت‌وگوی کاربر را (حداکثر ۲۰۰ پیام آخر) برمی‌گرداند و `DELETE` آن را پاک می‌کند. خروج از برد (حذف عضو) گفت‌وگوی او روی آن برد را هم حذف می‌کند. مدل با خروجی ساختاریافته `{reply, operations}` پاسخ می‌دهد. عملیات (`create_card`، `update_card`، `move_card`؛ ساخت و ویرایش می‌توانند جزئیات کارت و فهرست `labels` را هم تنظیم کنند و `null` یعنی بدون تغییر؛ AI فقط از برچسب‌های موجود استفاده می‌کند و برچسب نمی‌سازد) اعمال نمی‌شوند، بلکه پیشنهاد می‌شوند: با `board_service` در یک تراکنش آزموده و برگردانده (rollback) می‌شوند. اگر همه معتبر باشند در `operations` برمی‌گردند؛ وگرنه `operations` خالی است و `error` پر می‌شود. تاریخ امروز در پیام سیستمی است تا مدل تاریخ‌های نسبی را تبدیل کند. پیام سیستمی «facts» (`board_facts`) را هم دارد که برای گزارش‌ها محاسبه شده‌اند: شمار کارت هر ستون، کارت‌های انجام‌شده این هفته (در آخرین ستون و با `moved_at` در ۷ روز اخیر)، کارت‌های تازه این هفته، کارت‌های عقب‌افتاده و با سررسید در ۷ روز آینده (به‌جز آخرین ستون) و شمار کارت‌های باز هر مسئول. همچنین دستور تقسیم کارت (۳ تا ۷ کارت `create_card` در همان ستون) و نوشتن پاسخ بدون Markdown را دارد. کارت‌ها `created_at` و `moved_at` (آخرین تغییر ستون؛ UTC) دارند که در API برد نمایش داده نمی‌شوند. پاسخ: `{reply, operations, error}`. `POST /api/ai/apply` (بدنه `{board_id, operations}`) پیشنهاد را همه یا هیچ اعمال می‌کند (اگر برد از آن زمان تغییر کرده و جور نباشد 409) و `{board, undo}` می‌دهد. `undo` شامل کارت‌های ساخته‌شده، فیلدهای قبلی کارت‌های تغییرکرده و ترتیب قبلی ستون‌های درگیر است. `POST /api/ai/undo` (بدنه `{board_id, undo}`) با `board_service.restore_cards` آن را برمی‌گرداند: کارت‌های ساخته‌شده حذف می‌شوند، فیلدها و ترتیب برمی‌گردند، کارت‌هایی که از آن زمان حذف شده‌اند نادیده گرفته می‌شوند و کارت‌های تازه آن ستون‌ها در پایین می‌مانند. همه شناسه‌ها باید از همان برد باشند (وگرنه 409). خروجی خراب مدل خطای 502 می‌دهد. `POST /api/ai/chat/stream` همین کار را به‌صورت NDJSON انجام می‌دهد: خط‌های `{"type": "delta", "text"}` در حالی که مدل پاسخ را می‌نویسد (`partial_reply` متن فیلد `reply` را از JSON نیمه‌کاره بیرون می‌کشد، مستقل از ترتیب فیلدها)، سپس یک خط `{"type": "done", ...}` با همان نتیجه، یا `{"type": "error", "status", "detail"}` اگر وسط کار خطا شود (502، 503 یا 429). بررسی دسترسی پیش از شروع جریان انجام می‌شود (401/404 معمولی).
- `static/` — خروجی ایستای Next.js که در Docker از `frontend/out` کپی می‌شود (در git نیست؛ در اجرای محلی بدون آن، `/` خطای 404 می‌دهد).
- `tests/` — آزمون‌های pytest؛ `conftest.py` پیش از import برنامه `DB_PATH` را به یک پوشه موقت می‌برد و برای هر آزمون یک پایگاه داده موقت می‌سازد و فیکسچرهای `client` و `auth_client` (واردشده) دارد.

## اجرای آزمون‌ها

اگر `uv` به‌صورت محلی نصب نیست، داخل کانتینر uv اجرا کن (از ریشه پروژه):

```bash
docker run --rm -v "$PWD/backend:/src" -w /src -e UV_PROJECT_ENVIRONMENT=/tmp/venv ghcr.io/astral-sh/uv:python3.13-bookworm-slim uv run pytest -q
```

با `uv` محلی: `cd backend && uv run pytest`. پس از تغییر وابستگی‌ها `uv lock` اجرا شود.

آزمون‌های `live` واقعاً ارائه‌دهنده هوش مصنوعی (Groq یا OpenRouter، طبق `.env`) را صدا می‌زنند و به‌طور پیش‌فرض اجرا نمی‌شوند. برای اجرا، `.env` را به کانتینر بده و `-m live` بزن:

```bash
docker run --rm --env-file .env -v "$PWD/backend:/src" -w /src -e UV_PROJECT_ENVIRONMENT=/tmp/venv ghcr.io/astral-sh/uv:python3.13-bookworm-slim uv run pytest -q -m live
```
