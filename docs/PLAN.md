# مراحل اجرای پروژه

این سند نقشه اجرای MVP است. عامل هوش مصنوعی پس از انجام هر مورد، آن را با `[x]` علامت می‌زند. هر بخش فقط وقتی تمام‌شده است که همه آزمون‌ها و معیارهای موفقیت آن برقرار باشد.

## تصمیم‌های تأییدشده

| موضوع | تصمیم |
| --- | --- |
| احراز هویت | بک‌اند `user`/`password` را بررسی می‌کند و یک کوکی سشن امضاشده و HttpOnly می‌دهد؛ همه APIهای `/api/board` و `/api/ai` به آن نیاز دارند |
| ذخیره تغییرات کاربر | APIهای جزئی (هر اقدام یک درخواست) |
| خروجی AI | یک پاسخ متنی به کاربر و فهرست اختیاری عملیات: `create_card`، `update_card`، `move_card` (بدون حذف) |
| تاریخچه چت | فقط در حافظه فرانت‌اند؛ با هر درخواست ارسال می‌شود و با رفرش پاک می‌شود |
| پایگاه داده | ماژول استاندارد `sqlite3` بدون ORM |
| پورت | `8000` (آدرس `http://localhost:8000`) |
| ساختار ستون‌ها | پنج ستون ثابت؛ فقط نام آن‌ها قابل تغییر است |

## ساختار نهایی پوشه‌ها

```
backend/      FastAPI (app/، tests/، pyproject.toml، uv.lock)
frontend/     Next.js با خروجی ایستا (out/)
scripts/      start/stop برای Windows (.ps1) و Mac/Linux (.sh)
docs/         PLAN.md، DATABASE.md، schema.json
Dockerfile    ساخت چندمرحله‌ای: Node برای فرانت‌اند، Python+uv برای اجرا
.env          OPENROUTER_API_KEY (در git نیست)
```

- **مدل رایگان:** به درخواست کاربر، مدل از `openai/gpt-oss-120b` (پولی) به یک مدل رایگان OpenRouter تغییر کرد. از میان مدل‌های رایگانی که خروجی ساختاریافته strict را پشتیبانی می‌کنند، پنج مدل با آزمون‌های live چت سنجیده شدند. `particle-ai/particle-1:free` در همه اجراها پاس شد و سریع‌ترین بود؛ `nvidia/nemotron-3.5-super-vl:free` و `dots-studio/dots-3-note-preview:free` هم پاس شدند و جایگزین مناسب‌اند. مدل با `OPENROUTER_MODEL` در `.env` قابل تغییر است. مدل‌های رایگان OpenRouter محدودیت تعداد درخواست دارند.
- **کش مرورگر:** `index.html` بدون `Cache-Control` ارسال می‌شد و مرورگر پس از بازسازی ایمیج نسخه قدیمی را نشان می‌داد. حالا صفحه‌ها با `Cache-Control: no-cache` ارسال می‌شوند (فایل‌های هش‌دار `/_next/static/` همچنان کش می‌شوند).

علت: سهمیه رایگان OpenRouter برای کل حساب است (۵۰ درخواست در روز برای همه مدل‌های رایگان، بدون خرید اعتبار) و در روز ساخت توسعه ۶ تمام شد.

- [x] `app/ai.py` با جدول `PROVIDERS`: Groq (`openai/gpt-oss-120b`) وقتی `GROQ_API_KEY` تعریف شده باشد، وگرنه OpenRouter؛ `AI_PROVIDER` و `AI_MODEL` برای انتخاب دستی
- [x] گزینه `provider.require_parameters` فقط برای OpenRouter فرستاده می‌شود
- [x] کاربر کلید Groq را در `.env` می‌گذارد
- [x] آزمون‌های زنده روی Groq: هر شش آزمون پاس شدند (خروجی ساختاریافته strict با `openai/gpt-oss-120b` کار می‌کند)

یافته‌ها:
- یک درخواست چت با برد نمونه ۱۰ کارتی حدود ۱۸۰۰ توکن مصرف می‌کند (۱۷۰۰ توکن ورودی، بیشترش JSON برد). لایه رایگان Groq سقف توکن در دقیقه دارد؛ چند پیام پشت‌سرهم ممکن است پاسخ ۴۲۹ («سهمیه ... تمام شده») بگیرد و پس از چند ثانیه دوباره کار کند. برد بزرگ‌تر یعنی توکن بیشتر در هر پیام.
- Groq در حالت خروجی ساختاریافته strict پاسخ را یک‌جا می‌فرستد (یک تکه، حدود ۱٫۵ ثانیه)، نه تدریجی. مسیر تدریجی توسعه ۶ درست کار می‌کند و فیلد `reply` اول نوشته می‌شود، ولی روی Groq متن یک‌باره ظاهر می‌شود.
